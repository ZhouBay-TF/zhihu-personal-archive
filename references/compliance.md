# 合规与上传风险

这份说明不是法律意见，只帮助你判断“要不要上传到知乎 Skill 市场”。

## 结论先说

**这个 Skill 的核心能力（自动登录态采集、批量导出回答、拉取邀请/推荐）很可能不符合知乎的平台规则，至少属于高风险灰色地带。**

不建议直接上传到知乎 Skill 市场。更稳妥的做法是：只在本人电脑上本地使用，低频、手动登录、只处理自己的内容，不公开分发。

## 可能踩到的点

1. **自动化访问**
   知乎用户协议通常禁止使用自动化程序、脚本、爬虫、数据挖掘工具等方式访问或批量收集平台数据。本 Skill 使用 Chrome 调试协议和知乎接口，属于自动化访问。

2. **登录态/个性化数据**
   邀请和推荐需要登录后才能读取，属于账号个性化数据；批量拉取比公开热榜风险更高。

3. **内容下载与再分发**
   下载自己的回答用于个人备份，和把工具公开上传、让他人批量下载，是两件事。后者更容易被认定为协助抓取/传播平台内容。

4. **平台 Skill 审核**
   Skill 市场通常要求内容合法、无安全风险、不破坏平台生态。一个“自动抓取知乎内容”的 Skill 很可能被审核拒绝，甚至影响账号。

5. **热榜也不能完全当成“随便抓”**
   热榜是公开数据，但公开可见不等于允许自动化批量采集；仍应遵守 robots、服务条款和合理频率。

## 如果只是自己用

相对稳妥的做法：

- 只在本机运行，不部署成公开服务。
- 只处理本人账号内容。
- 手动扫码登录，不保存密码，不绕过验证码。
- 每天最多一次，不并发、不循环重试。
- 遇到 401/403、验证码、访问过于频繁立即停止。
- 不把导出的内容、Cookie、Chrome 配置目录上传或分享。
- 不把本 Skill 打包成公开商品/公开 Skill。

## 如果仍想上传到知乎

先做这几件事：

1. 阅读知乎当前的服务条款、社区规范、robots 规则和 Skill 市场审核规范。
2. 把“自动抓取/批量导出”改成“用户手动导入自己导出的文件”，只保留公开热榜的只读展示。
3. 不上传任何账号数据、Cookie、Chrome 配置、个人备份。
4. 在说明里写清楚“仅限本人内容、个人备份、低频、非商业”，但不要指望这样就一定合规。
5. 如果平台明确禁止自动化访问或数据采集，**不要上传**。

## 更安全的替代方案

- 只在本地保留这个 Skill，作为个人备份工具。
- 公开分享时，只分享“如何手动导出/整理”的教程，不分享自动采集脚本。
- 如果要做公开产品，先获得知乎的书面授权或使用官方开放接口。
